## Story

**As the** owner,
**I want** the 4 real `alunos` rows created by mistake from "Exp " experimental
walk-ins removed from the `alunos` table and their booking preserved as a
Comercial prospect occurrence instead,
**so that** they stop being counted as matriculados and instead show up where
they always should have: the Comercial/prospects list.

## Acceptance Criteria

1. Every `alunos` row with `nome ILIKE 'exp %'` is identified by exact `id`
   before any write (never a broad `DELETE ... WHERE nome LIKE`).
2. For each, any `grade_base`/`excecoes_semana` row referencing it via
   `aluno_id` is updated **first** — `aluno_id = NULL`, `tipo = 'comercial'`,
   `aluno_nome_avulso = <name, "Exp " prefix stripped>` — before the `alunos`
   row is touched. `grade_base.aluno_id`/`excecoes_semana.aluno_id` are both
   `ON DELETE CASCADE` to `alunos`; doing this in the other order would
   destroy the booking along with the (desired) presença/alerta cleanup.
3. The `alunos` row is then deleted (real `DELETE`, not soft-delete via
   Story 5.2's `situacao='removido'` — owner-confirmed: no notes/presença
   history needs preserving for a one-off experimental class).
4. After migration, each formerly-"Exp" prospect is findable on
   `/admin/comercial` (via `getProspectosComerciais`) grouped by their
   (now prefix-free) name, and absent from `alunosMatriculados`/
   `novasMatriculas` in `getRelatorioMatriculas`.
5. `alunos` rows with no linked booking anywhere (checked across
   `grade_base`, `excecoes_semana`, `aulas_presenca`, `aulas_notas`,
   `aulas_licoes`, `alertas_status`) are deleted directly — nothing to
   repoint.
