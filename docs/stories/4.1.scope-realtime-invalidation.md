# Story 4.1: Scope `useRealtimeGrade`'s invalidation to affected query keys

## Status

## Story

**As a** user with the app open on any screen,
**I want** a Realtime change on one table to only refetch the queries that
actually depend on that table,
**so that** an unrelated edit elsewhere (e.g. someone changing the grade while I'm
looking at the aniversariantes report) doesn't refetch every active query on my
screen.

## Acceptance Criteria

1. `useRealtimeGrade` (`src/hooks/use-realtime-grade.ts`) no longer calls
   `qc.invalidateQueries()` with no arguments. Each subscribed table's
   `postgres_changes` handler invalidates only the query-key prefixes that
   consume that table's data.
2. The query-key → table mapping is derived from actually reading each of the 19
   current call sites (`grep -rln "useRealtimeGrade()" src/` matches 20 files —
   one is `src/hooks/use-realtime-grade.ts` itself, the definition, not a call
   site; exclude it, e.g. `grep -rln "useRealtimeGrade()" src/routes/`; re-count at
   implementation time, this grew from Story 2.2's 17 after Story 6.1/6.2 added
   `admin.comercial.tsx`), not guessed. Follow the scoped-invalidation pattern
   already used elsewhere in this codebase (`professora.tsx:925-926`:
   `qc.invalidateQueries({ queryKey: ["lancamentos-semana"] })` — React Query's
   prefix matching means this also matches `["lancamentos-semana", dataSegunda,
professoraId]`).
3. Every screen that currently receives a live update via `useRealtimeGrade`
   continues to receive one after the change — this is a scoping fix, not a
   feature removal. Spot-check at minimum: `admin.index.tsx` (grid editor) and
   `professora.tsx` (professora view) both still refresh live when the other
   changes the grade.
4. Tables not touched by a given event no longer cause unrelated queries (e.g.
   `["matriculas"]`, `["aniversariantes"]`, `["carga-professoras"]` on the
   relatórios pages) to refetch.
5. `npm run typecheck` and `npm run lint` pass. Which 5 tables are subscribed
   (`professoras`, `grade_base`, `horarios_config`, `excecoes_semana`,
   `aulas_licoes`) does **not** change — that's Story 2.2's decision, out of
   scope here.
