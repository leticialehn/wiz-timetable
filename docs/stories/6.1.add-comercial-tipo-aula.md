## Story

**As a** secretaria,
**I want** a "Comercial" cell type with 4 fixed 15-minute slots per period,
**so that** I can schedule prospective clients for enrollment conversations without
occupying a real teaching seat or a book-tracked class slot.

## Acceptance Criteria

1. `TipoHorario` (`src/lib/types.ts`) gains `"comercial"`. `CAPACIDADE.comercial = 4`,
   `ROTULO_TIPO.comercial = "Comercial"`, `TIPO_MOSTRA_LIVRO.comercial = false`,
   `TIPO_FECHADO.comercial = false`. `TipoAula` (`Exclude<TipoHorario, "break" |
"preparacao_homework" | "sem_aula">`) picks it up automatically — do not add it to
   the exclusion list.
2. A generalized `slotMinutosPorTipo: Partial<Record<TipoHorario, number>>` (or
   equivalent) replaces the hardcoded `20` inside `slotsOnlinePorPeriodo`, with
   `online: 20, comercial: 15`. Rename/refactor to a single
   `slotsFixosPorPeriodo(tipo, periodo)` that returns `[]` for tipos without fixed
   sub-slots, preserving `slotsOnlinePorPeriodo`'s existing output for `"online"`
   byte-for-byte (same strings, same order) — this is a refactor, not a behavior
   change for Online.
3. `src/routes/admin.index.tsx`'s cell-rendering branch (currently
   `if (tipo === "online") { … }`, line ~462) is generalized to
   `if (slotsFixosPorPeriodo(tipo, periodo).length > 0)` so "Comercial" gets the
   same fixed-slot-by-position rendering Online already has, with zero duplicated
   JSX/logic.
4. Secretaria can configure a "Comercial" cell on any período/professora via the
   existing cell-type picker (`admin.index.tsx` line ~56's tipo list) — no new
   restriction beyond the `requireRole(["secretaria"])` guard every other cell-type
   edit already has (Story 1.3).
5. Booking a name into a Comercial slot uses the exact same free-text
   `aluno_nome_avulso` path every other avulso booking uses today (`grade.functions.ts`) — no
   new server function, no new DB column, no write to the `alunos` table.
6. **Database migration** (blocked until EPIC-002 Story 2.1's baseline lands — see
   epic Dependency): a new, named migration file adds `"comercial"` to the CHECK
   constraints on `horarios_config.tipo`, `grade_base.tipo`, and
   `excecoes_semana.tipo`. Applied via `supabase db push` against the (by-then
   reconciled) migration history — not a Studio edit, not an ad-hoc `DO $$` block.
7. `npm run typecheck` and `npm run lint` pass. Existing "Online" cells (both in the
   grid editor and the professora-facing view, `professora.tsx`'s `ehOnline`
   check) render identically before and after the refactor — spot-check at least
   one populated Online cell in each view.

## Dev Notes

- **Exact current mechanism (grounded 2026-09-14):** `slotsOnlinePorPeriodo`
  (`types.ts:409-414`) hardcodes 20-minute offsets from `HORARIO_INICIO_PERIODO`.
  `admin.index.tsx:462-519` is the only place that branches on `tipo === "online"`
  for rendering; it maps each fixed slot string to a `CelulaAula` by
  `horario_especifico`, falling back to `LinhaVaziaEditavel` (empty, bookable) or
  `LinhaVagaTrancada` (closed) per slot. `professora.tsx:708`'s `ehOnline` is a
  separate, simpler check for the read-only professora view — confirm whether it
  needs the same generalization or can stay Online-specific (it does not render
  sub-slot pickers, just a badge/label as of this grounding — recheck at
  implementation time).
- **Booking mechanism confirmed already generic:** `grade.functions.ts`'s
  `aluno_nome_avulso` path (used by "Exp" experimentais today) requires no changes
  — Comercial bookings are just another avulso under a new `tipo`.
- **Do not touch:** `alunos` table/type, `requireRole` guard logic (Story 1.3),
  any other `TipoHorario`'s capacity/label/behavior.
- **Sequencing:** Task 4 (migration) is the only task blocked on EPIC-002 Story
  2.1. Tasks 1-3, 5 (app code, using a local/dev Supabase or just typecheck/lint)
  can proceed independently, but the feature is not end-to-end functional against
  production until Task 4 lands — do not mark this story Done with Task 4
  incomplete.
