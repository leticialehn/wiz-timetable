## Story

**As a** secretaria looking at the Comercial prospects list,
**I want** a "MATRICULADO" button per prospect that turns their name and nível
into editable fields I can confirm,
**so that** enrolling a prospect who decided to join doesn't require the grid
editor at all, and lets me fix their name/nível (the level they enroll at
doesn't always match the level of the experimental class they tried).

## Acceptance Criteria

1. Each prospect row on `/admin/comercial` has a "MATRICULADO" button.
2. Clicking it reveals inline nome (pre-filled with the prospect's grouped
   display name, editable) and nível (empty, required) fields for that row.
3. Confirming calls the existing `criarAluno({nome, nivel})` — the same
   function the grid's own "type a new name" flow already uses — creating a
   real `alunos` row. No new server function needed.
4. This is a **fresh enrollment**, not a migration of the prospect's
   historical Comercial occurrences — the new `alunos` row isn't linked back
   to their past `excecoes_semana`/`grade_base` rows. Explicit scope
   boundary (see EPIC-007's Risks), not an oversight.
5. After confirming, the row shows a "Matriculado ✓" indicator instead of
   the button, for the rest of the current session (client-side only — no
   DB flag exists to track this, since a prospect isn't a DB row itself).
6. `npm run typecheck` and `npm run lint` pass.

- **AC4's scope boundary** was an explicit decision this session, not
  scope-cutting under time pressure: linking the new `alunos` row back to
  the prospect's Comercial history would need either a new join table or
  reusing `aluno_nome_avulso` matching (fragile — names can be typo'd
  differently across occurrences, which is exactly why `Lead` groups by
  normalized name in the first place). Out of scope unless the owner asks.
