## Story

**As a** maintainer,
**I want** `npm run lint` to actually finish and pass repo-wide,
**so that** the pre-push hook and epic-level quality gates (EPIC-001 AC9) are honest
checks instead of a command that hangs and gets silently skipped.

## Acceptance Criteria

1. `eslint.config.js`'s `ignores` array includes `.vercel` (currently gitignored via
   `.gitignore` but **not** excluded from eslint, which is a separate mechanism —
   eslint does not read `.gitignore` by default in flat-config).
2. `npm run lint` (`eslint .`, repo-wide, no path scoping) completes and exits — it
   must not hang or grow unbounded in memory. Confirmed baseline: it currently runs
   past 180 seconds and its `node` process was observed at 460+ MB and still growing
   before being killed, consistent with walking the ~4.9 MB / 154-file generated
   `.vercel/output` bundle.
3. `npm run lint` reports **zero** `prettier/prettier` line-ending ("Delete ␍")
   errors, caused by `core.autocrlf=true` (a local, per-machine git setting — not
   something a commit can change) checking files out as CRLF while `.gitattributes`
   (`* text=auto eol=lf`) and Prettier's default `endOfLine: "lf"` both expect LF.
   Fix by setting `"endOfLine": "auto"` in `.prettierrc` (Prettier preserves each
   file's existing line ending instead of forcing LF) — this does not touch what git
   stores (`.gitattributes` still normalizes the repository to LF) and does not
   require every contributor to change their local `core.autocrlf`.
4. No unrelated file changes: this story does not run a repo-wide
   `git add --renormalize .` or touch `core.autocrlf`. Scope is limited to the two
   config edits above.
5. After the fix, `npm run lint` and `npm run typecheck` both pass with exit 0 on the
   current `main`, and the `.husky/pre-push` hook (`npm run typecheck && npm run
lint`) succeeds end-to-end.
6. `npm run build` still succeeds (the `.vercel` ignore must not affect anything the
   build reads — it only excludes generated build output from linting).

## Dev Notes

**Dependencies:** None. Independent of 1.1–1.5 (touches only `eslint.config.js` and
`.prettierrc`, neither read by the auth code those stories changed). It is,
however, the last item blocking EPIC-001 AC9's closure.

**Complexity:** Trivial (T-shirt: XS) — two one-line config edits, no application
code touched. Risk is essentially zero: both edits are additive/config-only and
Task 3's verification step (`npm run lint`/`typecheck`/`build` + simulated
pre-push) catches any regression before Done.

**Risks:** The only realistic risk is scope creep — reaching for
`git add --renormalize .` or flipping `core.autocrlf` to "fully fix" line endings
project-wide. AC4 exists specifically to block that; it's a legitimate follow-up
but a much larger, separately-reviewable change.

- **Grounding for AC1/AC2:** confirmed this session — `.vercel` is in `.gitignore`
  but absent from `eslint.config.js`'s `ignores` array (read in full: only `dist`,
  `.output`, `.vinxi`, `src/routeTree.gen.ts`, and various `.<tool>-core/**`
  framework dirs are excluded). `.vercel/output` contains 154 `.js`/`.mjs` files
  (4.9 MB) of Nitro/Vercel-generated server bundle. Running `npm run lint` in this
  session did not complete within 180 seconds; `Get-CimInstance Win32_Process`
  confirmed the running process was `node .../eslint/bin/eslint.js .` at 460+ MB
  RSS and still climbing when killed. This matches QA-1.4-02's account of the same
  gate hanging/getting OOM-killed across Stories 1.3 and 1.4's QA passes.
- **Grounding for AC3:** `git config --get core.autocrlf` → `true` in this
  environment. `.gitattributes` line 2: `* text=auto eol=lf`. `.prettierrc` (read in
  full) has no `endOfLine` key, so Prettier defaults to `"lf"` and reports every
  CRLF line ending as a diff (`Delete ␍` in `prettier/prettier`). This is a known,
  documented Prettier footgun on Windows checkouts of LF-normalized repos; the
  standard fix is `endOfLine: "auto"` (Prettier docs: "Maintain existing line
  endings"), not fighting the local git config.
- **Why not fix `core.autocrlf` instead:** it's a per-machine git config, not
  repo-committed state — a story commit cannot change what another contributor's
  Windows checkout does. `endOfLine: "auto"` is the fix that lives in the repo and
  works regardless of each contributor's `core.autocrlf`.
- **Why not `git add --renormalize .`:** that rewrites git's stored blobs, which is
  a legitimate one-time cleanup but is a much larger, higher-blast-radius diff
  (touches every text file's stored line endings) than this story's actual problem
  (Prettier fighting the working-tree checkout). Out of scope per AC4; revisit
  separately if `.gitattributes` compliance is audited later.
- This is the last item blocking EPIC-001 AC9 (`docs/estado.md`, `docs/qa/gates/1.4-remove-attach-supabase-auth.yml` issue QA-1.4-02). The other half of AC9 — the
  manual auth walkthrough — was resolved 2026-09-14 (see `docs/estado.md` log and
  `docs/qa/gates/1.{1,2,3,4}-*.yml` `resolution` fields).
