# Story 7.1: Comercial cells never auto-create a real `alunos` row

## Story

**As a** secretaria booking a prospect into a Comercial slot,
**I want** typing a new name there to never create a real `alunos` record,
**so that** prospects stay prospects (only `getProspectosComerciais`) and never
silently inflate `getRelatorioMatriculas`'s matrícula counts — the bug already
did this for real, for "Exp " experimental-class walk-ins (see EPIC-007).

## Acceptance Criteria

1. `LinhaVaziaEditavel`'s inline cell editor (`admin.index.tsx`) never calls
   `criarAluno` when `tipo === "comercial"` — books via `aluno_nome_avulso`
   instead, using the same `adicionarAluno` server function every other
   avulso booking already uses.
2. No "Escolha um nível" validation blocks a Comercial booking (a prospect
   isn't a real aluno yet, so has no nível to choose) — the nível `<select>`
   is hidden entirely for Comercial cells in this editor.
3. Comercial bookings are always scoped `"semana"` (this-week-only), never
   `"base"` (permanent weekly template) — found during implementation: the
   existing "Avulso (só esta semana)" checkbox defaults unchecked, which
   would silently create a _permanent_ recurring slot for a one-off prospect
   if the secretaria forgot to check it. Forced `avulso = true` for
   Comercial, checkbox hidden (nothing to choose).
4. No regression to any other tipo's existing "type a new name → create a
   real aluno" behavior — that's correct everywhere else (a new name in a
   regular/vip/online/etc. cell usually is a genuinely new student).
5. The separate "add to any period" modal (`CelulaEditor`, `avulsoNome`
   state) was independently confirmed to already be avulso-only for every
   tipo — no change needed there, verified by re-reading `confirmarAdicao`
   in full: it only ever sends `aluno_id` (existing) or `aluno_nome_avulso`
   (free text), never calls `criarAluno`.
6. `npm run typecheck` and `npm run lint` pass.

  slot) — found while implementing, not invented scope creep. A prospect
  showing up once for an experimental class becoming a permanent weekly
  template slot if the secretaria forgets a checkbox is the same class of
  bug this story exists to fix.
- **Not verified live in a browser** — Chrome automation hit an unrelated
  environment issue this session (port 8080 resolved to a different,
  unrelated local project's dev server from the Windows-side browser,

  Verified instead: `npx tsc --noEmit` passes clean across the entire
  prop-threading chain (`GradeTabela` → closure → `handleCriarEAdicionar`),
  which is strong evidence the wiring is correct (a mismatched signature
  anywhere in that chain would fail to compile), plus manual trace of every
  code path touched.
