## Story

**As a** secretaria,
**I want** to mark a specific professora/período/day with a one-off note
(e.g. "Atividade especial — Dia das Crianças") that professoras see
directly on the grid,
**so that** I can replace the old paper-and-marker-pen workflow for
one-off special activities, without it becoming a permanent weekly thing.

## Request (owner, 2026-09-23)

> "Na semana que vem por exemplo, eu vou ter dia de atividade extra pro
> dia das crianças em alguns horários. Normalmente eu pintava esse
> horário de canetinha no papel pras professoras identificarem que aquele
> horário tem uma atividade especial somente naquele dia. Como podemos
> fazer isso agora?"

## Design

Two mechanisms already existed and were close-but-not-quite this:

- `HorarioConfig.tema` (`setHorarioConfig`) — a note on a cell, but
  **permanent, every week** (tied to `dia_semana`, not a specific `data`).
  Wrong shape: a Dia das Crianças activity happens once, not every
  Tuesday forever.
- `CalendarioExcecao` (feriado/recesso/férias) — date-specific, but
  **whole-school, per nível**, drives lesson-progression math. Wrong
  shape: this is about one professora/período, not shifting every
  student's calendar.

Neither fit "one date, one specific cell, just a visible note." Built a
third, narrower mechanism: reused `excecoes_semana` (already has
`data`/`dia_semana`/`periodo`/`professora_id`/`observacao`) with a new
`tipo_excecao` value, `'tema'` — a row that carries only a note, no
`aluno_id`/`aluno_nome_avulso` at all.

## Acceptance Criteria

1. New `tipo_excecao` value `'tema'` allowed on `excecoes_semana`
   (migration widening the CHECK constraint).
2. In the "⋯" advanced cell editor, a new section lets the secretaria type
   a note for **that exact date** (the date currently being viewed in the
   grid) and save it — independent of the cell's tipo/tema (weekly)
   configuration.
3. Saving with empty text clears any existing note for that
   date+professora+período (same "empty = cleared" UX already used for
   `HorarioConfig.tema`).
4. The note renders directly on the grid cell, visible without opening
   the editor — a distinct amber banner with a 🎉 icon, above the normal
   cell content — for exactly that one date, not the whole week.
5. `getGradeSemana` exposes these as `temasDoDia: Record<string, string>`
   keyed by `` `${data}|${professora_id}|${periodo}` ``, computed from the
   already-fetched `excecoes_semana` rows for the visible week (no extra
   query).
6. `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` all
   pass.

## Dev Notes

- **Why reuse `excecoes_semana` instead of a new table**: it already has
  every column this needs (`data`, `dia_semana`, `periodo`,
  `professora_id`, `observacao`) and `getGradeSemana` already fetches the
  full week's worth of rows from it — adding a 5th `tipo_excecao` value
  was a one-line constraint change plus a filter, versus a whole new
  table + query + join.
- **One row per cell, not accumulating**: `definirTemaDia` deletes before
  (maybe) inserting, so re-saving replaces rather than stacking multiple
  notes for the same date+professora+período — matches how
  `setHorarioConfig`'s `tema` field already behaves (last write wins).
- **Not shown for `TIPO_FECHADO` cells** (break/preparação): those render
  through an early-return branch in `CelulaConteudo` that never reaches
  the new banner — acceptable, since those slots aren't teaching slots to
  begin with. Not exercised by this story's use case (a real class period
  getting a special activity).
