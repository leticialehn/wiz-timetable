## Story

**As a** developer maintaining this codebase,
**I want** a test runner installed and unit tests covering the pure domain
calculation functions,
**so that** a regression in nível/lição progression, alerta thresholds, or grade
slot math is caught by `npm test` instead of shipping silently to production.

## Acceptance Criteria

1. `vitest` is added as a dev dependency and configured via a **standalone
   `vitest.config.ts`**, not by adding a `test` block inside `vite.config.ts`.
   **Found in PO validation (2026-09-18):** `vite.config.ts` doesn't call Vite's
   own `defineConfig` — it wraps `@lovable.dev/vite-tanstack-config`'s
   `defineConfig`, whose own top-of-file comment warns "do NOT add [the
   preset's plugins, incl. `tsConfigPaths`] manually or the app will break with
   duplicate plugins" (this is CON-4 from `docs/prd.md`: "Keep the
   `@lovable.dev/vite-tanstack-config` preset; don't re-add its plugins"). A
   flat `test` key may not even thread through that wrapped config's schema,
   and touching `vite.config.ts` at all risks CON-4. A separate
   `vitest.config.ts` (Vitest supports one standalone, independent of
   `vite.config.ts`) sidesteps this entirely — no new bundler either way, still
   matches CON-5.
2. `npm test` (a new `package.json` script) runs the suite headlessly, no dev
   server or Supabase connection required — unit tests only, pure functions.
3. Unit tests exist for these already-exported pure functions, found by reading
   `src/lib/types.ts` and `src/lib/licoes.ts` directly (not invented):
   - `src/lib/licoes.ts`: `posicaoDaRevisao`, `maiorPosicaoAtingida`,
     `licaoSugerida`, `posicoesAlemDaR8`, `avisoLicao`, `mesesDeAtraso`,
     `dataInicioInferida`, `normalizarLicao`, `temTrackingDeLicao`.
   - `src/lib/types.ts`: `idiomaDoNivel`, `grupoDoNivel`, `corTextoLegivel`,
     `slotsFixosPorPeriodo` (include a regression test that `"online"`'s output
     is unchanged post-Story-6.1 refactor — `:00/:20/:40` — and `"comercial"`'s
     is `:00/:15/:30/:45`).
4. **`alertas.functions.ts`'s internal helpers are out of scope for this story** —
   `calcularSequenciaFaltas`, `calcularSequenciaNotaFalaRuim`,
   `calcularSequenciaEscritaPendente`, `elegivelParaGravacao`,
   `contratoProximoOuVencido` are module-private (not exported) and the exported
   functions that use them (`getAlertasAtivos`, etc.) hit Supabase directly — testing
   those needs either exporting the helpers or mocking the DB client, which is a
   bigger decision than this story's scope. Flagged as a natural Story 3.3 (or
   folded into a later story) once the harness exists.
5. Each tested function has at least one test per meaningfully distinct behavior
   (not just one happy-path assertion) — e.g. `mesesDeAtraso` needs a case at/under
   the threshold and one over it, `avisoLicao` needs both the "invalid jump" and
   "suspiciously large jump" cases from its recent story (commit `15a9784`).
6. `npm run typecheck` and `npm run lint` pass; adding Vitest does not change the
   behavior of any existing script (`dev`, `build`, `lint`, `typecheck`).
7. `docs/framework/tech-stack.md` (or wherever stack choices are documented) gets a
   short "Testing" entry: Vitest, how to run (`npm test`), what's covered/not yet.

## Dev Notes

- **Grounded 2026-09-18** by reading `src/lib/licoes.ts` and `src/lib/types.ts` in
  full, and grepping every `^export function`/`^export const` in both files —
  the function list in AC3 is exhaustive for what's pure and already exported in
  those two files, not a partial/invented sample.
- **Why not `alertas.functions.ts`'s pure helpers too (AC4):** they exist
  (`calcularSequenciaFaltas` etc., confirmed at `alertas.functions.ts:27/221/235`)
  and are exactly the kind of dense, regression-prone logic this epic exists for —
  but they're not exported, and the functions that call them
  (`getAlertasAtivos`, `getAlertasLicaoPendente`) also call Supabase directly in
  the same function body. Testing them needs a decision this story shouldn't make
  unilaterally: export the helpers (small, safe change) vs. mock the Supabase
  client (bigger investment). Recommend a fast-follow story once this harness
  exists and the team has a feel for the pattern.
- **`avisoLicao`'s recent history**: commit `15a9784`
  ("warn at data-entry time on invalid or suspiciously large jumps") landed right
  before this epic was drafted — good real-world regression case, not a
  hypothetical one.
- **No mocking library added in this story** — every function in scope (AC3) is
  pure (no I/O, no Supabase, no Date.now() without an injected/passed-in "today").
  If any turns out to secretly depend on wall-clock time or another impure
  input, check whether the existing call sites already pass it in explicitly
  (most of this codebase's date logic takes an ISO string parameter rather than
  calling `new Date()` internally) before reaching for a mocking library.
