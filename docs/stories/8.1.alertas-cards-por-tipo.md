## Story

**As** Wizard/coordenação viewing `/admin/alertas`,
**I want** the page to open as a menu of clickable cards (one per alert
type, matching `/admin/relatorios`'s look), instead of one long page
mixing all 8 alert types together,
**so that** the view is cleaner and I can jump straight to the category I
care about.

## Request (owner, 2026-09-23)

> "Nos alertas, vamos criar botões como tem hoje da aba relatórios.
> Acredito que isso vai gerar uma visualização mais limpa. Então cada tipo
> de alerta vai para um botão diferente. Mas isso só deve mudar na
> visualização do adm, na tela das professoras permanece tudo igual."

Follow-up, after seeing a screenshot of `/admin/relatorios`: confirmed the
cards should look exactly like that page's — plain title + short
description, click through to the list.

## Acceptance Criteria

1. `/admin/alertas` shows a grid of cards, one per `TipoAlerta` (8 total),
   visually matching `/admin/relatorios`'s `RelatorioCard` style (title +
   short description, clickable, same border/hover treatment).
2. Each card additionally shows a small pending-count badge (reusing the
   same orange-pill style already used for the nav's "Alertas" badge) when
   count > 0 — extra utility beyond the Relatórios reference, since these
   numbers change day to day and matter for prioritization.
3. Clicking a card navigates to `/admin/alertas/<slug>` and shows exactly
   the list UI that existed before this story (same `AlertasLista`
   component, same pendente/resolvido grouping, same action buttons) —
   filtered to that one type via the pre-existing `apenasTipos` prop.
4. The "Aniversariantes do mês" banner (previously always shown atop the
   single alerts page) now shows once, on the new menu page — not
   repeated on all 8 per-type pages.
5. **`/professora/alertas` is untouched** — same single-page list, same
   `AlertasLista` call, same aniversariantes banner behavior. Not a single
   line in that route file changes.
6. `npm run typecheck`, `npm run lint`, `npm test` all pass.

## Dev Notes

- **Why a dynamic `$slug` route instead of 8 separate files**: the 8
  per-type pages are identical except for which `TipoAlerta` they filter
  to — a single parameterized route avoids 8x copy-pasted boilerplate
  that would drift out of sync over time. This codebase already has
  precedent for dynamic routes (`admin.alunos_.$id.tsx`).
- **Query-key reuse, not duplication**: the menu page's `getAlertasAtivos`/
  `getAniversariantesDoMes` calls use the exact same query keys
  (`"alertas-ativos"`, `"aniversariantes-do-mes"`) already used by the nav
  badge (`admin.tsx`) and by `AlertasLista` itself — React Query dedupes
  identical in-flight/cached queries across components, so this is not an
  extra round-trip, just a shared cache read.
- **`mostrarAniversariantes` defaults to `true`**: chosen specifically so
  that `professora_.alertas.tsx` — which was not touched — keeps its
  exact current behavior (it still shows the banner) without needing any
  edit to that file at all, satisfying AC5 by construction rather than by
  carefully avoiding a change.
