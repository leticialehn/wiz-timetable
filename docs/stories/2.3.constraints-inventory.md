## Story

**As a** developer about to add new columns/constraints (e.g., EPIC-006's "Comercial"
class type),
**I want** a single, verified inventory of every constraint (PK/UNIQUE/FK/CHECK) on
all 12 tables, confirmed against the live production catalog rather than just the
migration file,
**so that** I know exactly what I'm changing before I touch a CHECK constraint again —
the old migration history mutated these via anonymous `DO $$` blocks precisely because
nobody had this inventory.

## Acceptance Criteria

1. RLS + GRANT state of all 12 tables, from the actual production catalog: **already
   satisfied** by Story 2.1 (`docs/DB-AUDIT.md` §3, initial pass) and Story 2.2 (§3,
   reverified + extended after the Realtime decision). This story does not redo that
   work — it only needs a final cross-check that §3 still matches live prod
   (`pg_policies`/`information_schema.role_table_grants`), since the last verification
   was same-day and nothing has changed it since.
2. A new `docs/DB-AUDIT.md` section lists, for **all 12 tables**, every `PRIMARY KEY`,
   `UNIQUE`, `FOREIGN KEY` (with `ON DELETE` behavior), and `CHECK` constraint —
   sourced from a live query against prod (`information_schema` /
   `pg_get_constraintdef`), not just read off the migration file (the whole reason
   Story 2.1 exists is that the migration file and prod can silently diverge).
3. The known inconsistency across the three schedule-type `CHECK` constraints is
   explicitly documented: `horarios_config_tipo_check` allows `regular, online, vip,
reforco, conversacao, break, preparacao_homework, sem_aula` (8 values) while
   `grade_base_tipo_check` and `excecoes_semana_tipo_check` only allow `regular,
online, vip, reforco, conversacao` (5 values, `excecoes_semana`'s also permits
   `NULL`). State plainly that this blocks EPIC-006 ("Comercial" type) until reconciled
   — this story documents the gap, it does not resolve it (that's EPIC-006's job).
4. `docs/DB-AUDIT.md` §5 (Data-integrity notes) is updated to reference the new
   constraints section instead of restating individual facts inline.
5. No credentials committed; this is a read-only/documentation story — if it turns up
   any constraint that doesn't match the migration file (drift), stop and report it
   the same way Story 2.1 reported the RLS revert, rather than silently "fixing" it by
   editing the doc to match whatever prod happens to have.
6. `docs/estado.md` EPIC-002 table updated; if all of AC1-3 above close out every
   epic-level AC, note that EPIC-002 is ready for @po/@pm to consider closing (mirror
   how EPIC-001's closure was proposed in Story 1.6's aftermath — this story doesn't
   decide epic closure itself).

- **The EPIC-006 blocker (AC3)**: `horarios_config` already allows 8 `tipo` values,
  but `grade_base` and `excecoes_semana` only allow 5. A cell's `tipo` gets copied
  from `horarios_config`/`grade_base` into `excecoes_semana` when a week deviates
  from the template (per `docs/estado.md`'s EPIC-006 notes) — so today, only
  `regular/online/vip/reforco/conversacao` can safely round-trip through all three
  tables. Adding `comercial` (EPIC-006) needs the same value added to whichever of
  these three tables currently reject it, or the exception/copy path will fail its
  own CHECK constraint. This story documents the gap; EPIC-006 Story 6.1 resolves
  it.
- No `architecture/` docs beyond `docs/architecture.md` and `docs/DB-AUDIT.md` exist
  in this repo — same note as Stories 2.1/2.2.
