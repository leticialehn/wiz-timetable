## Story

**As a** coordenador or professor,
**I want** to be blocked from admin-only actions (editing the grid, cadastros,
calendário, users),
**so that** only the secretaria can change the school's configuration, while I can
still run my classes.

## Acceptance Criteria

1. After Story 1.2, these mutations additionally call `await
requireRole(["secretaria"])`: all writes in `cadastros.functions.ts`,
   `calendario.functions.ts`, `usuarios.functions.ts`, and the grid-editing writes in
   `grade.functions.ts` (`setHorarioConfig`, `removerHorarioConfig`, grade_base and
   excecoes_semana mutations).
2. Read endpoints and all `presenca.functions.ts` writes (presença/notas/lições) stay
   at `requireAuthenticated()` only — any papel may launch class records.
3. `alertas.functions.ts`: read endpoints require auth; the professora-scoped alert
   queries filter to `usuario.professora_id` unless the papel includes `coordenador`
   or `secretaria` (matches `TIPOS_ALERTA_PROFESSORA` / coordenadora behaviour already
   in `types.ts` comments).
4. A `professor`/`coordenador` session calling an admin-only endpoint gets
   `"Não autorizado. Você não tem permissão para esta ação."` and no DB change.
5. The admin nav / buttons are hidden or disabled for non-secretaria users (defense in
   depth; the server check is the real gate).
6. Checklist of endpoint → required role added to the Dev Agent Record.
7. `npm run typecheck` + `npm run lint` pass; pre-commit green.

## 🤖 CodeRabbit Integration

## Dev Notes

- `requireRole(papeis: Papel[])` is in `auth.server.ts`: calls
  `requireAuthenticated()` then throws unless `usuario.papeis` intersects `papeis`.
  `Papel = "secretaria" | "professor" | "coordenador"`.
- `usuario.professora_id` links a login to a `professoras` row (nullable, `UNIQUE`).
  Never trust a `professora_id` from the request body for authorization — read it from
  the session `usuario`.
- `types.ts` documents the coordenadora exception: "Coordenação vê funções extras
  (hoje: alerta de faltas consecutivas) que as demais professoras não veem."
- Grid editing lives in `grade.functions.ts`; class-record writes live in
  `presenca.functions.ts` — the split maps cleanly to secretaria vs any-papel.
- Keep changes minimal and mechanical; no refactor of the functions' internals.
