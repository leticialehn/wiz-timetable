## Story

**As a** professora,
**I want** to see the nível an experimental walk-in (or any other avulso
booking) is trying,
**so that** I know what to actually teach in that class, the same way I
already know it for every real matriculated aluno in the cell.

> "Funcionou. Ficou mto bom. Mas posso selecionar o nivel tb? Pra
> professora saber que nivel ele ira experimentar?"

## Root Cause / Gap

The "Nível" `<select>` in `LinhaVaziaEditavel` was already visible for
Experimental bookings (only hidden for Comercial — `!ehComercial`), so the
secretaria could already pick a value there. But `handleCriarEAdicionar`'s
avulso branch (`tipo === "comercial" || experimental`) never forwarded
`nivel` to `adicionarAluno` at all — it only got used on the _other_
branch, where a real `alunos` row is created via `criarAlunoFn({nome,
nivel})`. For an avulso/experimental booking (no real aluno), the typed
level was silently discarded. Neither `grade_base` nor `excecoes_semana`
even had a column to store it.

## Acceptance Criteria

1. New nullable column `excecoes_semana.nivel_avulso text` — free text
   (no FK/enum; matches how `aluno_nome_avulso` is already free text),
   `excecoes_semana` only (`grade_base` is always either a real aluno with
   its own `alunos.nivel`, or doesn't apply — permanent rows never come
   from an experimental/avulso flow that forces `escopo="semana"`).
2. Picking a nível in `LinhaVaziaEditavel` for an Experimental (or any
   other non-Comercial avulso) booking is sent through and persisted on
   `nivel_avulso`.
3. The grid shows that nível the same way it already shows a real aluno's
   nível (the existing book-icon badge in `LinhaPreenchida`) — no new UI
   element needed, the existing one just needed real data.
4. Comercial bookings continue to have no nível (the select stays hidden
   for `tipo==="comercial"` — a prospect who hasn't even tried a class
   yet has nothing to record).
5. `npm run typecheck`, `npm run lint`, `npm test` all pass.

## Dev Notes

- **No new UI element**: `LinhaPreenchida` already had
  `{mostraLivro && c.aluno_nivel && <span>...</span>}` rendering a level
  badge for every row — it was just always empty for avulso rows because
  the underlying data never existed. Populating `aluno_nivel` correctly
  for avulso/experimental rows was the entire fix; no new className, no
  new element.
- **Why not store nível in the existing `observacao` free-text field
  instead of a new column?** `observacao` already has its own display
  slot (the italic "· note" suffix next to the name) and its own meaning
  (free-form staff notes) — conflating it with nível would've either
  broken that existing use or required parsing/formatting logic to keep
  them apart. A dedicated column keeps both concepts clean and reuses the
  _existing_ level-badge UI, which is exactly the artifact the professora
  already reads for real alunos — consistency was the point of the
  owner's ask.
- **Comercial still has no nível** — the owner's original Story 7.1
  design decision (prospect hasn't chosen a level, "aluno ainda não
  existe") is unchanged. Only Experimental/other avulso bookings — where
  a specific level is actually being tried in a specific class — gained
  this.
