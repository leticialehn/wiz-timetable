## Story

**As a** maintainer of this repo (currently a solo/small team, per CON-5),
**I want** GitHub Actions to run typecheck, lint, and tests on every push and PR to
`main`,
**so that** a broken change is visible as a failing check before it's treated as
mergeable, not just relying on local husky hooks that can be skipped or missing.

## Acceptance Criteria

1. A new workflow file `.github/workflows/ci.yml` runs on `push` to `main` and on
   `pull_request` targeting `main`.
2. The workflow runs, in order: `npm ci` (not `npm install` — lockfile-exact,
   reproducible), `npm run typecheck`, `npm run lint`, `npm test` (once Story 3.1
   exists; if this story lands first, add the `test` step in the same PR that adds
   3.1, not as a silent no-op).
3. A failing step fails the workflow run visibly (GitHub's standard check-run
   behavior — no need for custom status reporting).
4. No secrets are required — per Story 3.1's AC2, all three commands run without a
   Supabase connection. If a future story needs one (e.g. integration tests), that
   requires an explicit new secrets-management decision, not assumed here.
5. The workflow uses a pinned Node.js major version via `actions/setup-node`
   (project has no `.nvmrc`/`engines` field today — pick and document one, e.g.
   matching whatever LTS the team already develops against; exact version is an
   implementation choice, not prescribed here) plus `npm`'s cache
   (`actions/setup-node`'s `cache: 'npm'`) so runs aren't slower than necessary.
6. This CI check does **not** replace or duplicate the existing local husky
   pre-push hook (`typecheck && lint`, confirmed in `.husky/pre-push`) — CI is a
   second, server-side gate that can't be bypassed by a missing local hook
   install, not a replacement for the fast local feedback loop.
7. `docs/framework/tech-stack.md` (or wherever CI is documented) gets a short
   entry describing what CI checks and where to see results.
