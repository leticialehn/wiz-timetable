## Story

**As a** secretaria,
**I want** a dedicated, top-level "Comercial" tab listing every prospect booked
into a Comercial slot,
**so that** I can follow up on enrollment conversations without digging through the
general "Leads" report, which mixes them with experimental-class walk-ins and other
avulsos.

## Dependency

Depends on Story 6.1 (the `"comercial"` `TipoHorario` and its bookings existing at
all). **Satisfied 2026-09-18** — Story 6.1 is Done (all 6 tasks, migration applied
and verified live against prod, `origin/main` at `84b2b14`), so `"comercial"` is a
valid `TipoHorario` end-to-end and bookable in the grid today.

## Acceptance Criteria

1. A new top-level nav link "Comercial" appears in `admin.tsx`'s header nav
   (alongside Alunos/Relatórios/Calendário/Professoras/Alertas — **not** nested
   under Relatórios, per explicit product decision), routing to `/admin/comercial`.
2. `/admin/comercial` lists every prospect booked under `tipo === "comercial"`,
   grouped/deduplicated by name using the same normalization
   (`normalizarNomeParaComparacao`) the existing Leads report already uses, so
   "Joao"/"João" collapse to one entry the same way.
3. A new server function (e.g. `getProspectosComerciais`) mirrors `getLeads`'s
   query shape (`grade_base` + `excecoes_semana`, filtered on
   `aluno_nome_avulso is not null`) but adds `.eq("tipo", "comercial")` — do not
   filter client-side; keep the query narrow like `getLeads`'s existing
   `.not("aluno_nome_avulso", "is", null)` pattern.
4. `getLeads` (existing) is updated to **exclude** `tipo === "comercial"` rows
   (`.neq("tipo", "comercial")` alongside its existing filters), so a Comercial
   prospect appears on `/admin/comercial` only, never also on
   `/admin/relatorios/avulsos`.
5. The new page reuses `admin.relatorios_.avulsos.tsx`'s structure (search box,
   grouped list, "última aula" style "última conversa" or similar date) rather than
   inventing a new UI pattern — visually consistent with the rest of `/admin`.
6. Both `/admin/comercial` and the now-filtered `/admin/relatorios/avulsos` are
   reachable only to authenticated users, same as every other `/admin/*` route
   today (no new auth work needed — inherited from Stories 1.1/1.2).
7. `npm run typecheck` and `npm run lint` pass.
