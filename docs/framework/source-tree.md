## `src/lib/` — domain logic

Two file suffixes carry hard rules:

| Suffix                                                                 | Bundles to client? | May import `client.server` at top level?          | Contains                                          |
| ---------------------------------------------------------------------- | ------------------ | ------------------------------------------------- | ------------------------------------------------- |
| `*.functions.ts`                                                       | **Yes**            | **No** — must `await import()` inside the handler | `createServerFn` RPC endpoints called from routes |
| `*.server.ts`                                                          | No (server-only)   | Yes                                               | Pure server helpers (auth, pagination)            |
| everything else (`types.ts`, `date-utils.ts`, `licoes.ts`, `utils.ts`) | Yes                | n/a                                               | Pure functions + types, no I/O                    |

Current inventory:

| File                                                                | Responsibility                                                                                                                                            |
| ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `types.ts`                                                          | **All shared types + domain constants + pure helpers** (níveis, períodos, capacidade, calendário, presença, papéis). Start here to understand the domain. |
| `date-utils.ts`                                                     | ISO-string date math for the schedule (weeks, weekdays). Prefer over raw `date-fns` for schedule logic.                                                   |
| `licoes.ts`                                                         | Lesson-progression math (R8 position, suggested next lesson, months behind pace).                                                                         |
| `grade.functions.ts`                                                | Computes the weekly grid (`grade_base` + `excecoes_semana` + `horarios_config` → `CelulaAula[]`).                                                         |
| `presenca.functions.ts`                                             | Presença / notas / lições writes; credit adjustment on presence transitions.                                                                              |
| `alertas.functions.ts`                                              | Derived alerts: consecutive faltas, rematrícula due, lesson not practiced, behind pace, birthdays.                                                        |
| `calendario.functions.ts`                                           | Feriados / recessos / férias (`calendario_excecoes`).                                                                                                     |
| `cadastros.functions.ts`                                            | Alunos / professoras CRUD.                                                                                                                                |
| `usuarios.functions.ts`                                             | User management (currently unreachable — no UI wired).                                                                                                    |
| `auth.functions.ts`                                                 | `login` / `logout` / `getSessaoAtual` / `criarPrimeiroUsuario`.                                                                                           |
| `auth.server.ts`                                                    | Session config, PBKDF2 hashing, `requireAuthenticated` / `requireRole` (**defined but unused** — see DB-AUDIT).                                           |
| `relatorios.functions.ts`                                           | Report queries (faltas, matrículas, níveis, carga, aniversariantes, declaração, avulsos).                                                                 |
| `supabase-paginacao.server.ts`                                      | `buscarTodasAsLinhas` / paginated fetch helper (Supabase 1000-row cap).                                                                                   |
| `error-capture.ts` / `error-page.ts` / `lovable-error-reporting.ts` | SSR error plumbing.                                                                                                                                       |

## `src/routes/` — routing conventions

File-based (TanStack Router). Naming:

| Pattern                                       | Meaning                                                                | Example                                     |
| --------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------- |
| `admin.tsx`                                   | layout route for `/admin` (renders `<Outlet/>` + nav)                  | `admin.tsx`                                 |
| `admin.alunos.tsx`                            | nested child `/admin/alunos`                                           |                                             |
| `admin.alunos_.$id.tsx`                       | trailing `_` = **break out of parent layout**; `$id` = path param      | `/admin/alunos/:id` without the admin shell |
| `admin.alunos_.$id_.historico.tsx`            | two breakouts, nested param page                                       | `/admin/alunos/:id/historico`               |
| `admin.relatorios_.faltas.tsx`                | report pages break out of the `relatorios` layout                      |                                             |
| `__root.tsx`                                  | app shell: `<html>`, head, QueryClientProvider, error + 404 boundaries |                                             |
| `index.tsx`                                   | `/` → `beforeLoad` redirect to `/professora`                           |                                             |
| `professora.tsx`, `professora_.aluno.$id.tsx` | teacher-facing screens                                                 |                                             |

Route file structure: `export const Route = createFileRoute("/path")({ component, head, beforeLoad? })`.
Data comes from server functions via `useServerFn(fn)` + `useQuery`, not route loaders (current convention).

## `src/components/`

- `ui/` — 46 shadcn primitives. Regenerate with the shadcn CLI (`components.json`); don't
  restyle in place unless the whole system changes.
- Root level — composite, domain-aware components: `AlertasLista`, `BoletimAluno`,
  `BuscaAluno`, `BuscaAlunoNaSemana`, `DeclaracaoAluno`, `HistoricoEditavel`,
  `LoginForm` (**not currently mounted**), `NotaEditavel`.

## Where new code goes

| You are adding…                      | Put it in…                                                                               |
| ------------------------------------ | ---------------------------------------------------------------------------------------- |
| A new screen                         | `src/routes/` following the naming table                                                 |
| A new server endpoint                | an existing `*.functions.ts` if the domain fits, else a new one                          |
| Server-only helper with secrets      | `*.server.ts`                                                                            |
| A pure calculation / new domain type | `src/lib/types.ts` or a dedicated pure module                                            |
| A reusable widget                    | `src/components/` (never in `ui/`)                                                       |
| A DB change                          | a new file in `supabase/migrations/` **and** regenerate `integrations/supabase/types.ts` |
